# ARCHITECTURE (condensed, 1 page)

> Scope: 1-page arch summary for agents. Full spec: `Documentation/1.Architecture.md`.
> Status: Active | Date: 2026-10-31

- **Request path:** Browser → Nginx (`storefront./admin./api.` domains) → Next.js apps (:3000/:3001) or NestJS service by `/api/<route>` prefix → Postgres/Mongo/Redis.
- **Event path:** producers never publish from a request handler: all five write an outbox row in the same transaction as the domain change (auth/cart/catalog/order → Postgres `<schema>.outbox`; cms → Mongo `cms_outbox`), and a relay from the shared **`@ecom/messaging` 0.2.0** package claims them — Postgres with `FOR UPDATE SKIP LOCKED` under one session advisory lock per schema, Mongo with repeated atomic `findOneAndUpdate` under a `<collection>_locks` lease document — publishes sequentially keyed by aggregate id, and marks them published; retry backs off on `locked_until` and parks at `failed` after five attempts. One `OutboxStorePort<Ctx>` has two implementations, so there is one relay and one retry policy for both databases. Consumers still inject `IEventBus.publish/subscribe` and the impl is `KafkaBus` in **every** environment (self-hosted KRaft; no env switch and no SNS adapter): topics + `.dlq` twins + replay, one consumer group per service (`postfixId` empty), `processed_events` dedupe. `ITaskQueue` (`SqsTaskQueue`) carries jobs only — `notify-send-email`, `import-process-row`, `media-resize-image`. `cms.updated` has **no** Kafka consumer: invalidation is **HTTP**, cms-svc calling the storefront's `POST /api/revalidate` with a shared secret (`x-revalidate-secret` + `{"tags":[…]}` → `revalidateTag(tag,'max')`), never Kafka — the arrow exists and is tested as of `sf-050`, and `cms-007` is the caller that does not exist yet. Storefront/admin hold no broker credentials: page views go `Next /api/track` → `analytics-svc` → Kafka. Envelope identical (`@ecom/contracts` 1.8.0).
- **Data:** DB-per-service, FKs only inside own schema; cross-service refs = logical UUID. Four Postgres outbox tables (`auth`, `cart`, `catalog`, `order` — the last one now an envelope table with `envelope`/`locked_until`/`last_error` and a nullable legacy `payload`) plus the Mongo `cms_outbox` collection; idempotency keys everywhere; saga-lite compensation on stock fail.
- **Producer outbox (§6.5, ADR 21-26):** the store quotes its identifiers (`"order"."outbox"` — `order` is a reserved word), validates the envelope and payload before the insert, and the relay is the only thing that publishes. There is no in-process producer bus left: catalog's `KafkaEventBus` and cms's `cms.events` publish are deleted, and `media.tasks` is the one publish still on the direct path until `cms-006` moves it to SQS. CMS invalidates its Redis cache **after** the Mongo transaction commits, never inside it.
- **Frontend:** Server Components fetch + `lib/cms/resolve.ts` (P>S>G) → dumb props; smart state only in route islands + `store/`.
- **Storefront seams (HTTP only, `sf-049`/`sf-050`):** exactly two arrows out of the UI, both HTTP. **Auth** — four BFF handlers (`app/api/auth/{login,register,refresh,logout}`) call auth-svc and own the `HttpOnly` cookies (`sf_at` 15m at `Path=/`, `sf_rt` 30d at `Path=/api/auth`; `Secure` in production), answering only `{user}`/`{ok:true}` so no token ever reaches client JS; `proxy.ts` forwards exactly one path, `GET /api/auth/session` → auth-svc `/me`, injecting the `Authorization` header server-side and stripping the inbound cookie, and guards `/account/*` + `/checkout/*`. **CMS** — every read is `fetch(…, { next: { tags: [cmsTag], revalidate: 300 } })` via `lib/cms/{client,tags,navigation,pageSettings}.ts`, so the Next Data Cache is the shared layer and the tag is the purge handle; `fetchNavSettings` cascades `cms-svc → a bounded 32-entry in-process TTL cache → DEMO_NAV_INPUT` and the root layout has no throwing path, so a cms-svc restart degrades the nav instead of blanking every route; `POST /api/revalidate` is secret-gated (constant-time over the SHA-256 of both sides, fails closed when `REVALIDATE_SECRET` is unset) and rejects any tag outside the shared vocabulary.
- **Deploy:** per-repo image → GHCR, `ecom-infra/VERSIONS.env` pins tags; one service at a time; rollback = revert one line. Health `/health` + `/health/ready`, `x-request-id` tracing, CloudWatch alarms.
